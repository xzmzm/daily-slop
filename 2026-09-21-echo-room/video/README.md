# Echo Room walkthrough

A 1920×1080, 20 fps H.264/AAC recording of the actual browser app, with Chinese Fish Audio narration, burned-in subtitles, matching SRT and exact app-generated tap samples in the narration pauses.

```sh
python -m pip install playwright pillow
python -m playwright install chromium
python 2026-09-21-echo-room/video/render_video.py
```

Requires `ffmpeg`, a Chinese font such as Noto Sans CJK, and `FISH_AUDIO_API_KEY` in the environment or ignored workspace-root `.env`. An existing environment value takes precedence. The key is passed directly to the established `2026-08-08-cattery/video/render_fish_video.py` helper and is never written into source, metadata, logs or screenshots. Model and voice remain `s2.1-pro-free` and `ae5adc6778ac459e8d6106b82f88fa2b`.

The opening correctly identifies this project's builder as GPT-6 Astra, rather than reusing the older GLM introduction. The spoken name is `GPT 六 Astra`. Subtitle lines and scene scripts live together in `render_video.py`. No year is spoken in this script; future additions should spell years digit by digit in Chinese.

`--preview /tmp/echo-room-checks` checks 1080p composition and asserts that subtitles do not overlap the experiment. `--captions-only` explicitly makes a non-narrated preview with subtitles and actual app audio; the normal publishing run requires narration and does not silently fall back. `--output PATH` changes the output destination.

The cursor is parked except for eased movements immediately before real clicks and drags. The viewport uses compact recording CSS while retaining the actual controls and model. Browser chrome displays the deployment URL and explicitly marks the recording as local. Simulation time is deterministic and visibly slowed to 0.06×. Audio stays at real speed and uses exactly the WAV samples generated by the app, with no per-preset volume normalization. Narration alone is mixed at 0.88 gain to leave headroom.

The GitHub workflow runs numerical tests, HTTP browser tests, layout preview, video rendering, full decoding, WAV/SRT checks, known-key and token-pattern scanning, then commits the finished media and gallery to main and triggers deployment. Temporary files live in an OS temporary directory; the scripts never use `rm`.
